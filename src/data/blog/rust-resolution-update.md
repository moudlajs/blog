In January I wrote about [tech resolutions that always fail by February](/posts/tech-resolutions-fail-by-february/). It ended with a promise:

> _I'm definitely going to learn Rust this year. For real this time. I'm very serious._

It's late September. Time for an honest status report.

## What I shipped in 2026

I checked my GitHub. This year I shipped side projects in:

- **Go.** A tool that turns a text file into an Apple Music playlist, and a fantasy football server for Claude.
- **TypeScript.** An NFL scoreboard.
- **Bash.** A save-game sync for two Macs. In bash 3.2, a version from 2006.
- **C#.** A command-line tool for my homelab.

Lines of Rust: **zero**.

## A timeline

**January.** Wrote the resolution. Felt productive.

**February.** Resolution failed on schedule. I did warn you.

**The rest of the year.** Every time a new project came up, I picked whatever got it done fastest. Go doesn't argue with me about lifetimes. Go barely argues about anything.

**September.** Wrote a Bash script with a built-in doctor, a lock file and conflict detection. Realised I'd put more safety engineering into a shell script than I ever put into learning Rust.

## What I actually learned

The January post said resolutions fail because they're written for a fantasy version of you. That turned out to be right, and a bit off.

I didn't learn Rust. But I shipped real, tested, released software this year, in four other languages. The resolution failed. The goal behind it, being a better engineer who builds things, kind of didn't.

I'll take that trade.

---

_P.S. - I'm definitely going to learn Rust next year. For real this time. I'm very serious._
